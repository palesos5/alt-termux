# Архитектура MIYABI OS

## 1. Ядро «kokoro» (心) — фасадная граница

Ядро делает ровно три вещи (фасад = тонкая оболочка, вся логика снаружи):

* **Прцессы/потоки.** BeOS-style team+thread, приоритеты `-20..20` (NICE).
* **Память.** `create_segment(size)` → сегмент с фикс. адресом; копия/резерв.
  MIPS4 R4000 TLB: 16 entries ITLB/DTLB, хэндлер refill на ассемблере, 4KB страницы.
* **Каналы.** Единственный межпроцессный механизм. Нет сигналов, нет сокетов,
  нет shared memory кроме сегментов-каналов.

### Канал = урезанный 9P

Сообщение — фиксированный пакет 256 байт (ничего не фрагментируется; большие данные
ходят через `Segment` + `flush` указателем, как `data`-файлы rio):

```c
typedef struct {
    u8  type;      /* Topen,Tread,Twrite,Tclunk,Tmode,Tevent,... */
    u8  tag;       /* запрос/ответ парами */
    u16 dev;       /* номер сервера: 1=kifu 2=kanzashi 3=fb 4=uart ... */
    u32 fid;       /* открытый файл на сервере */
    u32 off;       /* смещение */
    u16 count;     /* payload len */
    u16 mode;      /* ORAW|OWRITE|OMODE... */
    u8  data[240];
} Msg;             /* ровно 256B */
```

`chan_open(dev,path)`, `chan_read(w,msg)`, `chan_write(msg)`, `chan_wait(fid,evmask)`.
Сервер — обычный процесс, крутится в цикле `for(;;) handle(chan_read(q))`.

## 2. Драйверы — вне ядра

Драйвер это сервер-процесс, которому ядро даёт единственную привилегию:
`iowin(phys,size)` — отобразить физический диапазон в свой сегмент (как `/dev/mem`,
но per-driver whitelist из таблицы платформы). Прерывания доставляются сообщением
`Tirq` в канал драйвера. Всё: таймер — сервер `clock`, UART — сервер `console`.

Платформенные таблицы (никакой ACPI/OF, только compile-time константы 2004 года):

| Платформа | CPU | FB | Разрешение | Глубина | Регистры |
|-----------|-----|----|------------|---------|----------|
| SGI IP32   | R5000/R10000 32-bit KSEG | Magnum3B `H_GFX` | 1280×1024 | 8bpp palette | 0x94000000 |
| Cobalt Qube | Loongson-1 (RC3230-like) | SM712 | 800×600 | 4bpp gray | 0x1E000000 |

Обе машины имеют **3-кнопочную мышь** — средний кнопкой переключается большая модальность.

## 3. GUI-сервер «kanzashi» (簪 — шпилька, украшение фасада)

BeOS-подобный модель, но окна — файлы:

```
/dev/win/<id>/label      r/w   заголовок
/dev/win/<id>/geom       r/w   x y w h mode
/dev/win/<id>/pixels     w     RGB-palette индексы, damage-прямоугольники
/dev/win/<id>/events     r     mouse/kbd/expose/mode (текстовые строки)
/dev/win/<id>/ctl        w     "hide" "front" "modal <0|1|2>" "quit"
/dev/screen              r     снимок всего экрана (для скринсейверов)
```

Композитинг: сервер держит offscreen-буфер каждого окна, при `damage` копирует
прямоугольник в экран (double-buffered vsync по `Tirq` от `clock`). Никаких теней,
анимаций, шрифтов TrueType — встроенный 8×12 bitmap-шрифт (японские катакана-глифы
для названий окон, drawn вручную, 2004-approved).

События — текстом (как rio/acme, человекочитаемо):

```
mouse 12 44 L down
mouse 12 46 L drag
key 'q' press
mode 2            <- окно вошло в модальность M2
expose 0 0 320 200
```

## 4. Большая модальность (Large Modality)

Три уровня взаимодействия приложения, переключение средней кнопкой мыши или `Ctrl-E`:

* **M0 — Direct**: мышь манипулирует контентом напрямую (рисование, drag файлов).
* **M1 — Panel**: поверх окна появляется модальная полоса инструментов (BeOS Tracker
  style). Все клики идут в панель; контент замораживается, но *не блокируется* —
  другие окна работают (per-window modality, не system modal!).
* **M2 — Command**: нижняя 12px строка-«диапазон» (acme edit line). Клавиатура —
  команды вида `cut 3:7 paste` / `resize 400x300`. Строка парсится самим приложением.

Сервер хранит `mode` у окна; событие `mode N` асинхронно приходит клиенту,
и клиент сам решает что рисовать (сервер не знает о модах ничего кроме номера).
Это сохраняет фасад: политика в клиентах, механика в сервере.

## 5. Файловый сервер «kifu» (記録)

Один сервер, одна плоская ФС: образ на IDE = массив фикс. 512B блоков,
индекс в блоке 0 (суперблок), имена `flat`, директории = файлы со списком имён.
Нет прав, нет дат, нет ссылок. `/#/` префикс как в Plan 9: `/srv` каналы серверов,
`/dev` устройства-серверы, `/env`, `/lib/font`.

## 6. Boot

```
PROM (ARMON/YAMON) -> load 0x400000 -> kernel _start
  -> idt tlb init -> first process: /bin/init (user space!)
init: spawn drivers (fb,uart,clock,ide) -> kifu -> mount -> kanzashi -> /bin/shell
shell: запускает терминал + часы + welcome-draw
```

Всё после `_start` ядра — уже user space. Ядро не знает слова «файл».
